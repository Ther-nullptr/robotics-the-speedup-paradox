# 任务入口与依赖

协议先行，不把复现论文作为任何人的入门作业。当前已提供本地协作文件、schema 和 CPU 校验；远端规则及 CI 尚未启用/验证。Owner 在认领任务的 Issue 中填写，避免两位成员同时修改同一模块。

| 任务 | 依赖 | 能否无 GPU 推进 | 完成后带来的能力 |
| --- | --- | --- | --- |
| [001 数据契约演进](001-contract-evolution.md) | 当前样例与校验 | 是 | 将新需求落成兼容字段与负面案例 |
| [010 CPU 调度语义](010-cpu-scheduler.md) | 当前契约；必要扩展先走 001 | 是 | 用可手算时间线验证 sync/async/延迟 |
| [020 Trace 可视化](020-trace-viewer.md) | 当前契约样例 | 是 | 不依赖模型的状态与因果回放 |
| [030 Cosmos 接入](030-cosmos-policy.md) | 契约；真实对齐需上游代码/权重 | 部分 | 薄 adapter 和量化站点清单 |
| [031 LingBot 接入](031-lingbot-va.md) | 契约；真实对齐需上游代码/权重 | 部分 | cache 读写/重置契约 |
| [032 π0.5 接入](032-pi05.md) | 契约；真实对齐需上游代码/权重 | 部分 | reference policy 及可选 backend 边界 |
| [040 动态仿真](040-dynamic-simulator.md) | 010 | 先完成 CPU 部分 | 等待期间世界运动、对象状态与 delay profile |
| [050 第一例端侧优化](050-edge-optimization.md) | 任一真实 adapter + baseline profile | 性能部分需要设备 | 带精度/端到端证据的局部优化 |

建议第一轮由一人负责 010、一人负责 020，一位熟悉原代码的人梳理 030–032 的输入输出，维护者负责契约 review。模型方向可以并行做接口和 fixture，不必等待完整模拟器；真实实验与性能结论必须等相关实现和环境到位。

每张任务卡是一个可拆解工作包，不要求一次 PR 做完表内所有扩展。一次 PR 一个可解释行为。接口变更先合并契约，再让多个调用方依赖同一版本；不要多人各自修改不同的 trace 格式。
